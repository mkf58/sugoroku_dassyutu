# 仕様書ベース・テスト生成スキル

仕様書・設計書（Markdown）の内容をもとに、テスト観点の一覧化（テスト設計）および自動テストコードを作成します。

## 引数仕様
- `仕様書パス`（必須: 例 `docs/spec.md`）
- `対象コードまたはテスト出力先パス`（任意: 実装がある場合はそのファイル、未実装ならテストの配置先）
- `--cases-only`（任意）: テストコードは生成せず、テストケース設計・観点表の出力のみで完了する。

---

## 実行フロー

### 1. 仕様書（Markdown）の解析
1. 指定された仕様書を `Read` し、以下の情報を抽出・整理する：
   - **機能要件・ビジネスロジック**: 達成すべき計算、状態遷移、処理シーケンス
   - **入出力仕様**: 引数、戻り値の型、デフォルト値、制約条件
   - **バリデーション・エラーハンドリング**: 例外条件、エラーコード/メッセージ
   - **事前条件・事後条件**: 処理前後の状態（DB、キャッシュ、フラグ等）

### 2. プロジェクト環境の特定（テストコード作成時）
1. `Glob` でプロジェクト構造を確認し、使用言語やテストフレームワーク（Jest, Vitest, pytest, Go testing など）を自動検出する。
2. 既存のテスト規約（ファイル配置ルール、アサーションスタイル、モック方式）を把握する。

### 3. テストケースの設計（仕様網羅）
仕様書の記述に基づき、Markdown表形式でテストケースを整理して出力する。
- **正常系**: 仕様書で定義された主要シナリオ、代表値の網羅
- **準正常系 / バリデーション**: 不正入力、制約違反時のエラー・例外仕様
- **境界値・特殊条件**: 仕様書に書かれた閾値の前後（`x >= 100` なら 99, 100, 101 など）、null/空文字/空配列
- **デシジョンテーブル**: 複数条件の組み合わせ（フラグやロールごとの挙動）

> **※ 引数に `--cases-only` が指定されている場合は、この表を出力して終了する。**

### 4. テストコードの生成
1. 仕様書に記載された関数シグネチャ・インターフェースに基づきテストコードを記述する。
2. **実装が未作成（TDD）の場合**:
   - 想定される関数/クラスのインポート文を含め、仕様を満たすべきアサーションを網羅したテストを作成する。
   - インターフェースや型定義が必要な場合は、テストファイル内または対象言語の型ファイルとして最低限の宣言を補う。
3. **実装がすでに存在する場合**:
   - 仕様書の期待値と実装の整合性を確認しつつテストを記述する。
4. `Write` ツールでテストファイルを所定の場所（例: `tests/` や `__tests__/`）に書き込む。

### 5. 検証（Bash）
1. テスト実行コマンド（`npm test`, `pytest` など）を実行する。
   - **実装済みの場合**: テストがパスすることを確認。失敗時はテストコード側の不備（モック漏れ等）を自己修正する。
   - **TDD（未実装）の場合**: 構文エラー（Syntax Error）がないこと、および「未実装により正しくRed（失敗）になること」を確認して報告する。
