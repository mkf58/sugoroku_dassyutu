# make_project スキル

## ステップ1：モード選択

作業を開始する前に、ユーザーに以下を必ず口頭で提示し、番号で選択してもらうこと：

「make_project スキルを開始します。以下から実行モードを選択してください：

1. 新規プロジェクトを構成する（親フォルダ上の実行のみ有効）
2. 既存のプロジェクトをアップデートする（プロジェクトフォルダ内での実行のみ有効）
3. その他・相談する

番号を入力してください。」

- **1を選択** → 「モードA：新規プロジェクト作成」へ進む
- **2を選択** → 「モードB：既存プロジェクトのアップデート」へ進む
- **3を選択** → 「モードC：対話」へ進む

\```bash
cat << 'EOF' > AGENTS.md
# Project guide line

## プロジェクトの原則
- 本プロジェクトのプラン作成、および回答は全て日本語で行う
- スマホからのDiscordリモート操作に対応するため、以下の自律動作ルールを厳守すること：
  - 指示ファイル `instruction.md` から指示を受け取った場合は、速やかにタスクを実行する。
  - コードの修正や新規作成を行う際は、必ず新規の作業用ブランチ（例: `feature/xxx`）を切って作業を行い、変更をコミットしてリモートにプッシュすること。
  - ファイルの変更差分はGitで管理するため、成果物コード自体は結果ファイルに含めない。
  - 作業完了後、またはエラーで処理が中断した場合は、実行した内容のサマリー、プッシュしたブランチ名、および「次に行うべき提案（ユーザーへのメッセージ）」を `result.md` に日本語で書き込んで終了すること。

## 事前権限承認の設定（リモート運用時）
PC不在時のリモート動作中、コマンド承認ダイアログで停止するのを防ぐため、以下の権限のみを事前にエージェントに「常に許可（承認）」させておくこと。セキュリティの観点から、これら以外の不要なコマンド実行権限は許可しないこと。
1. プロジェクトフォルダ（ワークスペース）に対する `write_file` 権限（ファイル編集のため）
2. `git` コマンドに対する `command` 実行権限（ブランチ作成・コミット・プッシュのため）

## プロジェクトの目的
- 

# Memory & Handoff Instructions

## 3ファイルの役割と哲学
- 本ファイル（AGENTS.md）は「厳格なルール」、人が作成
- MEMORY.mdは「積み上がる経験」、AIが作成・AIが利用
- HANDOFF.mdは「セッション間の引き継ぎ」、AIが作成・AIが利用、ただし人間がレビューし必要な情報をキュレーションする

## セッション開始時（必須）
セッション開始時、ユーザーへの最初の応答の前に、以下のファイルを読み込み、プロジェクトの進め方・現状の進捗・共有事項を把握した上で、読み込んだ旨を報告すること：
- `.agent/memory/MEMORY.md`  （学習した知識・教訓）
- `.agent/handoff/HANDOFF.md` （前回の作業引き継ぎ）
- `.spec/PLAN.md` （プロジェクトの提案・QA・進め方）
- `.spec/TODO.md` （現在のタスク進捗状況）

## メモリ管理
- 新しい知識・教訓を記録する際は `.agent/memory/MEMORY.md` を更新
- 既存のMEMORY.mdを更新する前に、現在のファイルを`.agent/memory/YYYY-MM-DD.md` にアーカイブしてから新規作成
- ローカルの自動メモリ機能（~/.claude/ 配下）は使用しない
- MEMORY.mdは200行以内を維持すること
- 本ファイルと重複する内容はMEMORY.mdに書かない

## ハンドオフ管理
- ハンドオフは `/handoff` コマンドで作成（Claude Codeの場合）
- 保存先は `.agent/handoff/HANDOFF.md`（固定名）
- 作成時は既存ファイルを `.agent/handoff/YYYY-MM-DD-HHMM.md` にリネームしてからHANDOFF.mdを新規作成する
- 時刻はローカル時刻・24時間表記

## プロジェクト進め方の参照・共有ルール
AIエージェントは、作業を開始・継続する際、プロジェクトの内部フォルダを参照して常に最新の進め方・仕様・進捗を認識し共有すること：
1. **進め方の参照**: セッション開始時や新しいタスク着手時に `.spec/PLAN.md` および `.spec/TODO.md` を参照し、現在のフェーズと進め方を確認する。
2. **各フェーズのドキュメント参照**: 
   - 要件の確認・策定時： `要件定義/` 内のファイルを参照・作成
   - 基本設計時： `基本設計/` 内のファイルを参照・作成
   - 詳細設計時： `詳細設計/` 内のファイルを参照・作成
   - 単体テスト・実装時： `詳細設計/` の内容に沿って `実装コード/` を参照・作成
   - 結合テスト時： `基本設計/` をもとに `結合テスト仕様書_および_コード/` を参照・作成
3. **エージェント間・セッション間の共有**:
   - 作業内容や判定理由は `.spec/KNOWLEDGE.md` や `.spec/TODO.md` に適時記録・更新し、後続のエージェントやセッションが進め方を正確に参照できるように共有する。
4. **質問・確認事項のログ記録（重要）**:
   - エージェントがユーザーに確認や質問をする場合は、口頭（チャット）のみで済ませず、**必ず `.spec/PLAN.md` の「2. 深堀り・QA」セクションに質問事項を記述してログを残すこと**。ユーザーからの回答や擦り合わせ結果も `PLAN.md` に記録・反映して残す。

## テスト駆動型ウォーターフォール開発（TDD-WF）ルール
本プロジェクトは、テスト駆動開発（TDD）に近いウォーターフォール的な開発フローを基本とする。以下の順序・方針で開発を進行すること：
1. **要件定義**: `要件定義/` 内で要件と仕様を明確化する。
2. **基本設計**: `基本設計/` 内でドキュメントを作成。実装後の結合テスト仕様書へそのまま転用できる構成で記述すること。
3. **詳細設計**: `詳細設計/` 内でドキュメントを作成。そのまま単体テストコードに落とし込める具体的な粒度で記述すること。
4. **単体テスト作成**: 詳細設計からテストコード（自動テスト）を作成する。テストファイルは `実装コード/` フォルダ内の適切な場所に配置する。
5. **実装**: テストに合格するように `実装コード/` フォルダ内にプロダクトコードを実装する。
6. **結合テスト仕様書作成**: 実装完了後、基本設計をもとに `結合テスト仕様書_および_コード/` フォルダ内に結合テスト仕様書およびテストコードを作成する。
7. **結合テスト実施**: 結合テストを実施し検証する。

## 対話型アプローチと仕様定義フロー
- 作業の順序としては「提案（PLAN） → Q&Aによる深堀り → 仕様・設計策定（要件/基本/詳細） → テスト作成・実装」となる
- `.spec/PLAN.md`はユーザーの初期提案と、AI・ユーザー間のQ&Aシートとして活用する
- **質問・ログ記録の徹底**: エージェント側がユーザーに確認や質問をする場合は、**必ず `.spec/PLAN.md` に質問事項を書き込んでログを残すこと**。チャットでの応答内容も `PLAN.md` に追記して記録を保持する。
- AIはユーザーの提案を読んだらそのまま実装に入らず、要件定義や設計に必要な深堀り質問を `PLAN.md` に追記し、ユーザーが回答するサイクルを繰り返す
- Q&Aを通じて仕様が明確になった段階で要件定義・各設計ドキュメントを作成・確定させること
- 新しい開発サイクルを始める際は `/newplan` コマンドを使用してPLAN.md等をリセット・更新する

## フォルダ用途
- `要件定義/`：要件定義書用
- `基本設計/`：基本設計書（結合テスト仕様書のベース）用
- `詳細設計/`：詳細設計書（単体テストコードのベース）用
- `実装コード/`：プロダクトコードおよび単体テストコード用
- `結合テスト仕様書_および_コード/`：実装後の結合テスト仕様書・結合テスト用コード用
- `.spec/`：日々のタスク管理や作業起点メモ（PLAN / SPEC / TODO / KNOWLEDGE）
- `.output/`：成果物・アウトプット用
- `.references/`：参考資料・素材用

# モードB：既存プロジェクトのアップデート

## B-1. 現状の精査

本スキル（make_project）のモードAのA-3以降に記載されているすべての要素を正として、
現在のプロジェクトフォルダの状態と照合し、不足・未作成の要素をリストアップする。

精査完了後、以下を報告する：
「以下の差分が見つかりました。アップデートを適用してよいですか？
- 追加・作成するもの：[不足している要素の一覧]
- スキップするもの（既存）：[すでに存在する要素の一覧]」

ユーザーの承認を得てから B-2 に進む。

## B-2. 差分の適用

B-1で不足と判定された要素のみ、モードAの対応する手順を実行する。
既存ファイル・フォルダは上書きしない。
AGENTS.mdへの追記は既存内容と重複しないよう確認してから行う。

## B-3. 完了報告

適用した内容とスキップした内容の一覧を報告する。

# モードC：対話

ユーザーの相談内容をヒアリングし、このスキルの範囲でできることを提案する。
必要に応じてモードAまたはモードBへ誘導する。
