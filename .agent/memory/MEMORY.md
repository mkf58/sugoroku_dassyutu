# MEMORY

## プロジェクト概要
- タイトル（仮）：すごろく×魔女の館脱出 (Sacrifice & Dice in the Witch's Mansion)
- エンジン・言語：Godot Engine 4 (GDScript)
- ターゲット：PC (Steam / itch.io)
- ジャンル：ターン制すごろく脱出ホラーADV
- 開発方針：テスト駆動型ウォーターフォール開発（TDD-WF）

## 学習した知識・教訓
1. **ホラー作品の演出トーン：**
   - お涙頂戴や感傷的な演出を徹底して排し、冷徹に儀式を執行する乾いた質感を維持する。
   - CERO:C / PG-12相当を遵守し、ゴア演出は暗転・フォーリー音響（陶器破壊音等）で代替表現する。
   - 分岐選択肢を露骨に表示すると隠し要素がネタバレするため、条件達成時のみシームレスに特殊イベント（説得・逆走）を発生させる。
2. **ゲームシステム設計とバグ防止原則：**
   - 味方ユニット（主人公・少女）の操作コマンドは共通化（1.ダイス移動 / 2.アイテム使用 / 3.魔法使用 / 4.待機・祈る ＋ コマンド閉じる）し、状態遷移の複雑化とバグを防ぐ。
   - 魔法使用時は移動不可（移動と魔法の二者択一）とし、明快なボードゲーム的駆け引きを作る。
   - 土魔術の地中潜行中は「祈る」コマンド選択で潜行状態をそのまま継続できる。
3. **マス種別と状態管理の抽象化・シンプル化：**
   - イベント系マス（宝箱、石碑、痕跡、解放、介錯）は個別CellTypeに細分化せず、`EVENT` マス（＋`event_id`）に一元化する。
   - 階段（フロア遷移）と脱出（クリア）は本質的に同一であるため、`EXIT` マスとして統合する。
4. **リアルタイム判定とAI制御：**
   - 捕縛・水トラップ判定はターン終了時の一括処理ではなく、**1歩進むごとにリアルタイム判定**する（水トラップは侵入即ターンエンド、突破に丸1ターン消費）。
   - 魔女の追跡ターゲットは「最短距離の未潜行ユニット」を優先し、同距離時は `主人公 > 炎 > 風 > 水 > 土 > その他`。全員潜行時は初期配置位置へ移動する。
5. **ユーザーストレス軽減・快適性の設計原則：**
   - 運要素が強く理不尽に死ぬゲームだからこそ、それ以外のUI・テンポ・操作性でのストレスを徹底排除する。
   - 魔女のターゲット（ヘイト）を頭上アイコンで明示し、納得感のある死（良質な悔しさ）にする。危険域接近時は心拍SE＋画面減光で直感的に警告する。
   - 出目消費時の折り返し移動（行きつ戻りつ）を許可し、出目が大きすぎることによる強制突入事故を防ぐ。
   - UI操作は**『左クリック＝すべて確定・選択』『右クリック＝すべてキャンセル・閉じる』**を徹底厳守する。ホバーで点線矢印プレビュー表示。
   - 死亡演出スキップ（既読スキップ）、味方移動の画面クリック即時完了、エネミーの全員一瞬同時移動による待ち時間ゼロのテンポを担保する。
   - チラつくツールチップは排し、見たい時だけ見られるヘルプモーダル（マス一覧・基本ルール）に情報を集約する。
6. **ドキュメント管理ルール：**
   - 基本設計書は、実装後の結合テスト仕様書へそのまま転用できるよう、表形式の結合テスト観点（IT-UI, IT-TRN, IT-DAT）を必ず含めて記述する。
   - QAのログは必ず `.spec/PLAN.md` に残し、決定事項を速やかに要件定義書および基本設計書に反映する。
